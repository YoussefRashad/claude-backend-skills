# Working notes

Mechanics of working in this repo. Learned the hard way; not derivable from the files.

## Shell

- **Never put backticks in a `node -e` string.** Bash runs them as command substitution
  before node sees them — in one case starting a stray `nest new` and creating a file
  named `-`. Write a `.mjs` to the scratchpad and run it, or use a quoted heredoc
  (`<<'EOF'`).
- `cd` inside a Bash call **persists** to later calls. Prefer absolute paths.
- ESLint 9+ dropped `--format=compact`; plain `npx eslint <path>` is fine.
- `git status --short`: a letter in **column 1** means staged. After `git add -A` for a
  diffstat, `git reset` — nothing here should sit staged unless a commit was asked for.
- Empty directories are invisible to git (`templates/src/config/` is one).

## Verifying templates — they cannot be checked in-repo

This repo has no NestJS dependencies, so templates cannot be linted or compiled here.
Build a throwaway project in the scratchpad:

- **Lint/selector checks** — `npm i` the exact pins from `package-fragments.md`, copy
  `eslint.config.mjs` + `tsconfig*.json`, lint fixtures that should and should **not**
  trip each rule. A `no-restricted-syntax` selector that fails to parse breaks
  `npm run lint` for every repo, so validate before shipping one.
- **Money** — `money.util.ts` has zero dependencies: strip the type annotations with
  `sed` and run it under plain `node` to check arithmetic.
- **DI metadata** — compile a class with a value import and with `import type`, then
  `grep design:paramtypes` in the emitted JS. Value → `[Redis]`; type-only →
  `[Function]`.
- **Full scaffold** — `npx @nestjs/cli@11 new` (pin the major), apply the toolchain and
  templates, run all seven gates, **then boot it**. A green build proves nothing about
  startup: that is how the `compression` crash shipped.
- **Guard scripts** — test both directions. A guard that never fails is not a guard.

## Gotchas

- `simple-import-sort` sorts siblings by **regex index, not alphabetically**: nested
  paths come before flat ones (`./common/x` before `./app.module`).
- Every new file must be prettier-clean or `npm run check` fails — run
  `npx prettier --write` on anything you add, docs included.
- `.claude/settings.json` hooks need a **nested** `hooks` array
  (`[{matcher, hooks:[{type, command}]}]`); the flat shape is rejected.
- Editing this repo does **not** update the deployed skills at `~/.claude/skills/`.
  Re-copy them (README § Updating) before testing a change end to end.
