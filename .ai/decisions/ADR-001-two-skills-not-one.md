# ADR-001: Split the standards and the toolchain into two skills

## Status

Accepted.

## Context

Both a scaffolded service and an existing service need the same ESLint, Prettier,
tsconfig, Husky and lint-staged configuration. The obvious design is one skill that does
everything, so a single invocation produces a complete project.

The two jobs have different shapes, though. Applying the standards to a new project is a
create-from-nothing operation; applying a toolchain to an existing repository is a merge
that must preserve `baseUrl`, `paths`, `include`/`exclude` and project-specific hook
commands, and therefore needs per-file approval.

## Decision

Two skills. `backend-standards` **deliberately ships no** lint, formatter, compiler or
git-hook configuration and invokes `toolchain-config` at step 3 instead.

The dependency is one-way and mandatory: `backend-standards` checks that
`toolchain-config` is installed before step 3, and if it is missing says so plainly and
continues rather than substituting hand-written config.

## Alternatives Considered

| Option                                                              | Pros                                          | Cons                                                                         |
| ------------------------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------- |
| One combined skill                                                  | Single invocation; no install ordering        | Two copies of the eslint config in one repo, which is exactly how they drift |
| Two skills, as chosen                                               | One reviewed baseline; each skill has one job | Both must be installed; a scaffold can end up without a toolchain            |
| `backend-standards` writes config when `toolchain-config` is absent | Always complete                               | The fallback copy drifts silently — worse than a known-missing one           |

## Consequences

- A missing `toolchain-config` produces a **stated** gap rather than a silent second
  copy. `SKILL.md` marks hand-writing those files **MUST NOT**.
- `toolchain-config` is reusable on repositories that want nothing else from the
  standards.
- The two coordinate at exactly one point: the canonical `.prettierignore` lists
  `.ai/standards/` and `.claude/agents/`, so a toolchain re-sync does not reformat files
  that `backend-standards` vendored.

## Evidence

- `README.md` — "**They are a pair.** `backend-standards` deliberately does not ship lint
  or compiler config … because two skills shipping the same eslint config is how the two
  copies drift apart."
- `backend-standards/SKILL.md` § Requirements — "`toolchain-config` — required", with the
  MUST NOT on hand-writing substitutes.
- `backend-standards/README.md` § "Both skills are required".
