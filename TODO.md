## Blocking

### Nest 12 is not supported

`backend-standards/SKILL.md` step 1 pins the CLI to `@nestjs/cli@11`, because an unpinned
`npx @nestjs/cli new` now resolves to 12.x and generates a different baseline in six ways:
oxlint instead of ESLint, Vitest instead of Jest, `nodenext` module resolution (relative
imports need `.js`), TypeScript 6, `strict: true`, and no `useDefineForClassFields`
pinning at `target: ES2023`.

The last one matters most: the TypeORM hydration footgun that `toolchain-config` documents
at length is **live by default** on Nest 12.

Supporting it is a real piece of work — a second toolchain profile, or a decision to move
the fleet. **Raise with the owner.** Until then the pin holds and new services are on
Nest 11. See `backend-standards/SKILL.md` § "Nest 12".

## Inconsistencies

- **`project-setup`'s own `settings.json` template is out of date.** Its `hooks` example
  uses the flat `{matcher, command}` shape; the current schema requires a nested `hooks`
  array of `{type, command}`. The hook was therefore **omitted** here rather than written
  in an invalid shape. Formatting is already enforced by `npm run check` and CI, so
  nothing is lost — but if you want the hook, the correct shape is:

  ```json
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{ "type": "command", "command": "npx prettier --write \"$FILE\" || true" }]
      }
    ]
  }
  ```

  Verify the file-path variable actually interpolates before relying on it; a hook that
  silently no-ops is worse than none.
